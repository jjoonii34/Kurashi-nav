# ADR-0008: Tailwind CSS for frontend styling

- Status: accepted
- Date: 2026-11-22

## Context

The frontend (`web/`) is used on a phone right after a viewing, so every
screen is designed mobile-first (375px wide, see `docs/MVP.md` §7). The
styling approach had to be chosen when the app was scaffolded (M2-1).

Options considered:

- **Tailwind CSS** — utility classes in the markup; the `create-next-app`
  default; responsive variants (`sm:`, `md:`) are built in.
- **CSS Modules** — built into Next.js, no extra dependency; every
  responsive rule and spacing scale is written by hand.

## Decision

Use Tailwind CSS 4, wired through `@tailwindcss/turbopack` as generated by
`create-next-app` 16.4.6. `app/globals.css` imports it once.

## Consequences

- Two more dev dependencies (`tailwindcss`, `@tailwindcss/turbopack`). They
  run at build time only; the browser receives a plain CSS file containing
  just the classes the pages use.
- ADR-0001 (standard library first) covers Go modules; npm packages for
  `web/` are tracked by Dependabot instead.
- Long class lists can hurt readability; repeated combinations move into
  components, not into custom CSS classes.
