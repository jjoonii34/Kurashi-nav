## 1. 배경 (왜 바꾸나)

사용자가 계약 전에 실제로 묻는 질문 기준으로 현재 데이터를 점검한 결과:

| 사용자 질문 | 현재 (MVP v1) | 판정 | 보완 |
|---|---|---|---|
| 이 위치 안전해? | 홍수·고조·쓰나미·토사·액상화 | **지진 누락** (일본 최대 리스크) | R2: J-SHIS 지진 해저드 |
| 이 건물 안전해? | 없음 | **누락** | R3: 築年月 입력 → 구 내진기준 경고 |
| 이 월세 적정해? | 주변 **매매** 거래가 (F3) | **질문과 불일치** | R1: e-Stat 지역 평균 **집세**와 비교 |
| 초기비용 정상이야? | 사용자 입력 + 규칙 (F4) | 충분, 근거 보강 | R4: 중개수수료 법정 상한 경고 |
| 생활 편해? | 용도지역·학구 | 부분 | R5: 의료기관 등 시설 레이어 (P2) |
| 방 크기 괜찮아? | 사용자 입력 (F5) | 충분 | — |

핵심 원칙: **판정하지 않고 참고 범위를 보여준다.** 공적 임대료 통계는 계속임대료 중심이라
실제 신규 계약 시세와 차이가 날 수 있다 (국토교통성도 같은 한계를 인정). 모든 비교는 "참고"로 표시.

## 2. 공통 제약 (모든 항목에 적용)

- **ADR-0002 (사용자 입력 비저장·비로그·제3자 비전송):**
  - 새 입력값(`area_sqm`, `built_year_month`)은 로그·저장 금지.
  - 외부 API에 **정확한 핀 좌표를 보내지 않는다.** 좌표는 서버에서 **地域メッシュ 코드**(JIS X 0410)로
    변환한 뒤 메시 단위로 조회한다 (R2). 캐시 적중률도 올라간다.
  - 시구정촌 판정이 필요하면 좌표를 메시 중심점으로 거칠게 만든 뒤 사용한다 (R1).
- **외부 API는 서버에서만 호출.** 기존 레이트리밋(초당 1회 + 버스트 10)·singleflight·24시간 캐시 패턴 재사용.
- 새 섹션도 기존과 같이 `ok` / `unavailable` 두 상태. 실패해도 200 + `partial: true`.
- 3개 국어(en / ko / やさしい日本語) 메시지 필수.
- 출처·크레딧은 `internal/source/source.go`, `docs/DATA_SOURCES.md`, `/v1/meta/sources`에 반영.
- API 계약 변경 시 `docs/openapi.json` 갱신 → `internal/server/openapi_test.go` 통과.
- 응답 시간 목표(하우징 p95 ≤ 2초 캐시 적중 / ≤ 6초 콜드)를 넘기지 않는다. 새 외부 호출은 기존 병렬 조회에 합류.
- **도메인 판정 기준(등급 경계값, 경고 문턱)은 `TODO(human)`** — 사람이 직접 작성 (§9.3 기준).
  아래에 적힌 수치는 "후보"이며, 사람이 원문을 확인한 뒤 확정한다.

## 3. 요구사항

### R1. 월세 비교 — F3 개편 (우선순위 P0, 가장 가치 큼)

**목표:** "이 월세가 이 동네에서 비싼 편이야?"에 공공 통계로 참고 답을 준다.

**데이터:** 총무성 「住宅・土地統計調査」(令和5年 = 2023년 10월 1일 시점) — e-Stat API
- 시구정촌별 **민영 차가(民営借家)** 평균 월세, 1畳당, **専用住宅의 1㎡당** 평균 월세
- 주의: 敷金·礼金·권리금·共益費·管理費는 **포함되지 않음** → 비교 시 사용자 월세도 管理費 제외 값 사용
- 주의: 시정촌 데이터는 **시(市)와 일부 정(町)만** 공표 → 없는 지역은 도도부현 값으로 대체하거나 `unavailable`
- (선택, P2) 「小売物価統計調査」: 도도부현청 소재지·인구 15만 이상 도시의 3.3㎡당 민영 家賃, 월별

**설계 결정 (ADR 초안 A):** 5년 주기 통계이므로 **실시간 호출하지 않고 정적 테이블로 내장**한다.
- `cmd/gen-rent/`: e-Stat API로 해당 표를 받아 `internal/rent/data/rent_2023.json` 생성 (`make gen-rent`)
- 런타임은 `go:embed`로 읽기만 → 지연 0, 외부 의존 0, 사용자 위치가 e-Stat으로 가지 않음
- e-Stat 앱 ID는 `.env`의 `ESTAT_APP_ID` (생성 도구에서만 사용, 서버 런타임 불필요)

**시구정촌 판정:** 핀 좌표 → 시구정촌 코드. 방법은 §7에서 검증 후 ADR로 결정.
- 후보 1: 이미 조회하는 reinfolib 레이어 응답에 시구정촌 코드가 있으면 재사용 (외부 호출 추가 없음, 최우선)
- 후보 2: 국토지리원 역지오코더 (메시 중심점 좌표로 호출)
- 후보 3: 국토수치정보 행정구역 데이터 내장 (무겁다, 최후)

**API 변경:**
- 입력 `cost`에 `area_sqm?: number` 추가 (전용면적). 없으면 ㎡ 비교 생략.
- 출력 `sections[]`에 `rent_benchmark` 추가:
  ```json
  {
    "id": "rent_benchmark",
    "status": "ok",
    "municipality": {"code": "13104", "name": "新宿区"},
    "survey": {"name": "住宅・土地統計調査", "as_of": "2023-10-01"},
    "area_avg_rent_per_sqm": 3120,
    "area_avg_rent_monthly": 98000,
    "user_rent_per_sqm": 3400,
    "ratio": 1.09,
    "band": "near_average",
    "summary": "…(3개 국어)…",
    "caveats": ["継続賃料を含む平均で新規募集賃料より低めに出やすい", "…"]
  }
  ```
  (필드명·형태는 구현 시 OpenAPI와 함께 확정)
- `band` 구간 경계(예: ±10%, ±25%)는 `TODO(human)`.
- 기존 매매 거래가(`price_summary`)는 삭제하지 않고 **"주변 매매가(참고)"** 로 강등해 결과 화면 하단으로 이동.

**완료 조건:** 생성 도구 테이블 테스트, 내장 데이터 로드 테스트, 시구정촌 미공표 지역 `unavailable` 테스트,
`area_sqm` 없음 케이스 테스트, OpenAPI 갱신, 프론트 결과 카드 + 견적 폼 필드.

### R2. 지진 해저드 — F1 추가 (P0)

**목표:** 핀 위치의 지진 흔들림 위험을 다른 재해와 같은 카드 형식으로 보여준다.

**데이터:** 방재과학기술연구소 J-SHIS 「地震ハザードステーション」 API
- 위도·경도 **또는 메시 코드**로 조회 가능 → **메시 코드로 조회** (§2 개인정보 원칙)
- 표시 후보 지표: "30년 내 진도 6약(震度6弱) 이상 흔들림이 올 확률" (確率論的地震動予測地図)
- 엔드포인트 버전·case·eqcode 파라미터·응답 필드는 §7에서 실호출로 검증

**구현:**
- `internal/mesh/`: 위경도 → 地域メッシュ 코드 변환 (1차·2차·3차·필요 시 분할 메시). 순수 함수 + 테이블 테스트.
  · 학습: 좌표계·정수 연산 (**직접 작성 권장**)
- `internal/jshis/`: 클라이언트. reinfolib 클라이언트와 같은 레이트리밋·singleflight·캐시 패턴 (메시 코드를 캐시 키로).
- `housing` 병렬 조회에 합류, 실패 시 `earthquake` 섹션만 `unavailable`.

**출력:** `sections[]`에 `earthquake` (등급 + 확률값 + 3개 국어 문장 + 출처).
- 등급 경계값은 `TODO(human)`. 후보: J-SHIS 지도 범례의 확률 구간(예: 3%, 6%, 26%) — **원문 확인 후 확정**.
- 문장에는 "확률이 낮아도 일본 어디서나 큰 지진은 일어날 수 있다"는 안내를 항상 포함.

**[직접]** J-SHIS 이용약관·크레딧 문구 확인 (M1-1과 같은 방식).

### R3. 건축연도 입력 → 구 내진기준 경고 (P0, 가장 작음 · 첫 작업으로 추천)

**목표:** 외부 API 없이 사용자 입력 한 칸으로 건물 안전성의 가장 큰 신호를 준다.

**입력:** `cost`(또는 별도 `building`) 에 `built_year_month?: "YYYY-MM"` 추가. 견적서·물건 정보의 「築年月」.

**규칙 (도메인 판정 → `TODO(human)`):**
- 신 내진기준은 **1981년 6월 1일 이후 建築確認**을 받은 건물에 적용된다.
- 사용자가 아는 것은 보통 **준공(築年月)** 이고, 건축확인부터 준공까지 시간차가 있다.
- 후보 구간:
  - 준공 ~1981-05 → `warning` "구 내진기준일 가능성이 높음"
  - 준공 1981-06 ~ 1983-12 → `check` "구/신 경계. 부동산에 建築確認日 또는 耐震診断 여부를 물어보세요"
  - 그 이후 → `ok`
  - (선택) 목조 단독주택이면 2000년 기준 개정 안내 — MVP에서는 생략 가능
- 출력: `sections[]`에 `building_age` 또는 F4 `warnings[]`에 합류 — 구현 시 결정, OpenAPI 반영.
- 부동산에 **물어볼 질문 문장**을 3개 국어로 함께 제공 (일본어 원문 포함: 「建築確認日はいつですか」「耐震診断はしていますか」).

· 학습: 날짜 경계 테이블 테스트

### R4. 중개수수료 법정 상한 경고 — F4 보강 (P1)

**목표:** 초기비용 경고에 법적 근거가 있는 기준을 추가한다.

**규칙 후보 (원문 확인 후 `TODO(human)`으로 확정):**
- 거주용 임대 중개에서 부동산 회사가 받는 중개수수료 **합계 상한 = 월세 1개월분 + 소비세 (1.1개월분)**.
- 한쪽(세입자)에게서 받는 것은 원칙 **0.5개월분 + 세**, 세입자가 사전에 승낙한 경우에만 1개월분까지.
- 경고 후보:
  - 수수료 > 월세 × 1.1 → `warning` "법정 상한을 넘을 가능성"
  - 월세 × 0.55 < 수수료 ≤ 월세 × 1.1 → `info` "0.5개월분을 넘는 경우 승낙서에 서명했는지 확인"
- 기준 출처(국토교통성 고시)를 `docs/DATA_SOURCES.md`에 기록.

**[직접]** 국토교통성 고시 원문 확인 → 문턱 확정.
